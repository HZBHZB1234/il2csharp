## The measurement correction that matters most

Three tiers exist and they were being confused:

1. **declaration tier** — what `tools/compile_corpus.py` / `gate.py compile`
   report: 19 errors (unitask) / 118 (survivors). **All of those are
   declaration-level and every one is traced** to a model artifact
   (CS0234 doubled namespace, CS0117 profile constants, CS8701 default-interface
   methods, CS0111 cross-image scaffolding, CS0051/52/53 internals) or a
   metadata-absent generic stub (CS0535).
2. **body tier** — the number that actually says whether the emitted code
   compiles. It only becomes visible once the declaration tier is clean,
   because **one declaration error makes Roslyn skip ALL method-body binding**
   (`docs/todo.md`, "FOUND: a declaration error suppresses ALL body binding").
   Measured per image with stub generation: **unitask 9,619**
   (publicized), survivors ~30,750 (normal model, needs the publicize rerun).
3. **publicized body tier** — the same measurement with `--publicize`, which
   removes our member-visibility spelling from the count. For unitask this
   collapsed 78,104 → **9,619**: the 68,111-error flood in
   `Unity.TextMeshPro` was accessibility, not lifting (that image went
   68,111 → **17**).

## Reverted, with the measurement that killed each (do not re-try blind)

1. **Pure-return duplication at goto sites** — UIElements gotos 562 → 562.
2. **Guard inversion** for `if (cond) { goto L; } ... L:` — never matched;
   the arms carry work and the label is far below.
3. **Redundant-jump dropping** (label after the enclosing if/else) — the label
   is not adjacent.
4. **House-type declarations for undeclared temps** (`num*`→int, `obj*`→object):
   CoreModule CS0103 364 → 92 but **total 3,893 → 3,913** — it converts name
   errors into conversion errors.
5. **`real*`-only declarations**: `Unity.TextMeshPro` 68,111 → 68,034 (0.1 %),
   and the missing names simply became `obj6`/`obj10`.

The through-line: these families are **unmodeled values**, not missing
declarations. Root cause found in the raw lifter output (round 52):
`ProfilerCategory.get_Name` reads `s_38` with **no write anywhere** in the body,
so `_rename_locals` renders an undeclared `num1` that no declaration pass can
rescue. The fix belongs in the lifter (model the callee's out/return that fills
the slot), not in text passes.
