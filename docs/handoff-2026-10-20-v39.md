### 2.1 `il2cpp/metadata.py` — v39 解析

- 版本上限：`24 <= version <= 39`；新增 `v35`、`v38` 两个版本标志。
- **头部**：v38+ 每个表是 `(offset, size, count)` 三个 i32，31 张表
  → 头部 380 字节。`self.hdr[name+'Count']` 只在 v38+ 存在。
- **变长索引**：`_vw(count)` / `_read_vw(off, width)`
  - 宽度 1/2/4 由表数量决定，`0xFF` / `0xFFFF` 解释为 -1。
  - `type_w` 来自运行时同样的公式：
    `parametersSize // parametersCount - 8`（Limbus 上为 4）。
- **TypeDefinition**（v38+，stride **82**）：
  `name u32, namespace u32, byval(type_w), declaring(type_w),
   parent(type_w), genericContainer(gc_w), flags u32, 8×i32 starts,
   8×u16 counts, bitfield u32, token u32`
  - 实测 `declaringTypeIndex` 是 **Type 索引（4 字节）**，不是
    Il2CppDumper 源码注解的 TypeDefinition 索引；这正是 82 字节的来源。
- **MethodDef**（v38+，stride **32**）：
  `name u32, declaring(td_w), return(type_w), returnParameterToken i32,
   parameterStart(param_w), genericContainer(gc_w), token u32,
   flags/iflags/slot/paramCount 4×u16`
- **ImageDef**（v38+，stride **36**）：
  `name u32, assemblyIndex i32, typeStart(td_w), typeCount u32,
   exportedTypeStart(td_w), exportedTypeCount u32, entryPoint i32,
   token u32, customAttributeRange 8 字节`
- **GenericParameter**（v38+，stride **14**）：
  `owner(gc_w), name u32, constraintStart i16, constraintCount i16,
   num u16, flags u16`
- **字符串字面量**（v35+）：不再有每行的 length，只有边界数组
  （`count = 字面量数 + 1`，最后一个是池大小）。存储为
  `(length, dataOffset)`，和旧格式一致。
  - 修过一个自己引入的 bug：最初存成 `(offset, length)`，
    `string_literal()` 反向解释，导致 `stringliteral.json` 写出 11.8 GB。
    修复后 32,124 条字面量总长 930,512 字节，与 pool 大小完全相等。
- `string_literal()` 增加越界保护。

### 2.2 `il2cpp/runtime/registration.py` — MetadataRegistration 锚点

`_find_metadata_registration()` 原来要求 `fieldOffsets[1..3]` 里至少 2 个
指针能读到小整数。v39 的 `<Module>`、无字段类型大量为 **NULL**
（Limbus 上前三个槽位只有 1 个非空），旧规则直接判定失败，报
`MetadataRegistration not found`。

现改为：

- 在 `fieldOffsets[1..min(64, td)]` 窗口内统计非空指针；
- 要求 `ok >= 2` 且 `ok * 2 >= seen`（不是全空）；
- 额外用 `typeDefinitionsSizes` 首项的 `instanceSize ∈ (0, 0x1000000)`
  做交叉校验。

## 3. 关键定位结果（Limbus 这份二进制）

```
metadata v39 | 51021 types | 319009 methods | 162 images | 32124 string literals
CodeRegistration      @ 0x1876D0740   （codeGenModules 字段 @ 0x1876D07D0）
MetadataRegistration  @ 0x1884EC040
module 指针数组        @ 0x188D33E70（162 项）
metareg: genericClasses=33738, genericInsts=25163,
         genericMethodTable=300187, types=122737,
         methodSpecs=355990, fieldOffsets=51021,
         typeSizes=51021, metadataUsages=0
registrations ok | 299281/319009 methods have native code
```

几个容易踩的点：

- v39 的 **CodeRegistration 是 17 个 qword**（`X - 16*8`），不是老代码
  注释里的 18 个。il2csharp 现有的相对偏移 `q(-16)..q(-1)` 与 17-qword
  布局**完全一致**，所以功能上没出问题；只有 `code_reg_va` 这个日志值
  仍按 `X - 18*8` 打印，比真实地址低 0x10，纯显示问题。
- 该结构后面紧跟 invoker 表（`invokerPointers = X + 0x20`），不要误以为
  结构延伸到 `X+` 后面。
- `metadataUsagesCount/Table` 为 0：Unity 6 已经不再生成 usage 表，
  但 metareg 末尾这两个 qword 仍占位（所以锚点仍是 `fieldOffsets` 前
  10 个 qword）。
